# 매쓰캔버스

> 비상교육 수학 수업 플랫폼의 관리자 프론트엔드 — 통합 SSO · CMS · 데이터 이관까지, 폐쇄망 안에서 기존 의존성만으로 완성.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.04 – 2026.09 |
| 고객사 | 비상교육 |
| 역할 | 관리자 프론트엔드 주 개발, 사용자 화면 기능 개발, 인수인계 문서 작성 |
| 기여도 | 관리자 커밋 220여 건 · 사용자 화면 커밋 120여 건 |

## 배경

매쓰캔버스는 교사가 수학 수업 활동을 만들고 공유하는 플랫폼입니다. 저는 콘텐츠 · 사용자 · 운영을 관리하는 관리자
화면을 주로 맡았습니다. 개발 환경은 새 npm 패키지를 설치할 수 없는 폐쇄망이었고, 리뷰를 거쳐 병합하는 팀이었습니다.

## 담당 업무

- **관리자:** 사용자 · 콘텐츠(캔버스 · 슬라이드 · 공유 · 라이브러리) · 에셋 · 가이드 CMS · 데이터 이관 · 대시보드
- **사용자 화면:** 활동 만들기, 나의 · 공유 프로젝트, 로그인 · 비밀번호 재설정, 가이드 뷰어
- **공통:** 통합 SSO 연동, API 마이그레이션, 리디자인

## 문제와 해결

### 1. 통합회원 전환

- **문제:** 서비스별 회원이 통합회원과 SSO 로 바뀌면서 로그인 흐름과 사용자 데이터 구조가 함께 달라졌습니다.
- **해결**
  - SSO 를 연동하고 마이페이지는 외부로 위임했습니다.
  - 사용자 목록 · 상세를 통합 ID 기준으로 바꿨습니다.
  - 요청에 따라 이름 · 학교 · 이메일 같은 개인정보 노출을 걷어냈습니다.
- **결과:** 관리자 화면에서 개인정보를 다루지 않고도 운영 업무를 할 수 있게 됐습니다.

### 2. 패키지를 설치할 수 없는 환경에서 워드형 에디터 만들기

- **문제:** 가이드 CMS 의 리치텍스트 에디터를 워드처럼 바꿔 달라는 요청이 있었는데, 플러그인을 새로 설치할 수 없었습니다.
- **해결**
  - 이미 있던 TipTap 확장만으로 글자 크기 · 줄 간격 · 이미지 크기와 정렬 · 목록 · 구분선 · 유튜브 삽입을 구현했습니다.
  - 초안을 로컬에 보존하고, 복원과 이탈 경고를 넣어 편집 유실을 막았습니다.
- **결과:** 사용자 화면의 가이드 뷰어도 같은 서식을 똑같이 렌더링하도록 맞췄습니다.

### 3. 백엔드 스펙 전면 변경

- **문제:** 관리자 API 경로와 응답 형태, 도메인 이름(mathclass → library 등)이 한꺼번에 바뀌었습니다.
- **해결:** 엔드포인트와 응답 매핑을 새 스펙으로 옮기고, 수동으로 쓰던 타입을 openapi-typescript 생성 스키마에서 파생하게 바꿨습니다.
- **결과:** 이후 스펙이 바뀌어도 스키마만 다시 생성하면 타입 오류로 영향 범위가 드러납니다.

## 주요 기능

- **데이터 이관 화면:** 작업 실행, 상태 폴링, 실패 작업 재시작, 파이프라인 형태의 실행 이력
- **리디자인:** Figma 컬러 토큰을 3계층(원시 → 시맨틱 → 컴포넌트)으로 재편, 사이드바 · 목록 테이블 · 대시보드 신설
- **라이브러리 관리:** 교구별 테마 콘텐츠 순서 관리, 슬라이드 → 라이브러리 복제(관리자 등급 전용)

## 협업

- 코드 리뷰를 거쳐 병합하는 팀이었습니다. 리뷰 지적(중복 호출 방지, 예외 흐름, 타입 가드)은 항목별 반영 커밋으로 나눠 추적할 수 있게 했습니다.
- 프로젝트를 마칠 때 부팅 순서, 인증, 라우팅 규약, API 타입 생성, 환경변수, 작업별 체크리스트를 담은 인수인계 문서를 작성했습니다.

## 배운 점

제약이 많은 환경일수록 **이미 있는 도구를 깊이 아는 것**이 새 도구를 들이는 것보다 강하다는 것을 배웠습니다.
리뷰 문화 속에서 일하며 "고친 이유를 남기는 커밋"의 가치도 체감했습니다.
