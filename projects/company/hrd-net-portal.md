# HRD-Net 훈련추천시스템 포털

> 한국산업인력공단의 AI 훈련 추천 시스템 — 백오피스와 학습자 진단 · 추천 화면을 하나의 SPA 로 혼자 만들고 온프렘으로 전달.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.06 – 2026.10 |
| 고객사 | 한국산업인력공단 |
| 역할 | 프론트엔드 단독 개발 |
| 기여도 | 프론트엔드 100% (커밋 420여 건) |
| 기술 | Vue 3.5, TypeScript, Vite 6, Pinia, vue-router, vue-i18n, Tailwind v4, Chart.js, D3, xlsx |

## 배경

학습자가 사전역량진단을 하면 AI 가 맞춤 훈련 콘텐츠를 추천하는 시스템입니다. 기관과 관리자는 백오피스에서 학습자,
콘텐츠, 추천 이력을 관리합니다. 운영본은 공단 내부 온프렘 서버에 있고, 학습자 화면은 기관 사이트에 iframe 으로
들어갑니다.

## 담당 업무

- 학습자 진단 → 추천 흐름 전체(설문 · 결과 · 추천 목록 · 지식맵 · 피드백)
- 백오피스 전체(대시보드 · 기관 · 관리자 · 학습자 · 콘텐츠 · 커넥터 · 추천 이력 · 이벤트 · 서버 관리)
- 게이트웨이 API 연동, 배포 구성(개발 Kubernetes, 운영 온프렘 패키지)

## 문제와 해결

### 1. 학습자 화면을 다른 시스템에도 옮겨 써야 한다

- **문제:** 학습자 진단 화면은 다른 추천 시스템에도 그대로 들어가야 했습니다. 그런데 관리자 화면과 코드가 얽히면 옮길 수 없고, 학습자 토큰으로는 부를 수 없는 관리자 API 가 섞여 들어갈 위험도 있었습니다.
- **해결:** survey 모듈이 호스트 기능(api · toast · 라우팅 · 추적)을 `SurveyHost` 인터페이스로만 주입받게 했습니다. 양방향 import 금지는 경계 테스트로 검사합니다.
- **결과:** 폴더째 다른 시스템에 옮길 수 있는 독립 모듈이 됐고, 같은 종류의 결합이 다시 들어오지 못하게 됐습니다.

### 2. 운영 환경의 제약

- **문제:** 공단 내부망이 PATCH · DELETE 요청을 막았습니다. 운영본은 온프렘이라 한 번 배포하려면 다른 회사 담당자가 직접 올려야 했습니다.
- **해결**
  - 차단된 요청은 POST 로 바꿨습니다.
  - 온프렘(JWS/httpd)용 배포 패키지와 설치 가이드를 만들었습니다.
  - 개발 · v2 · 온프렘 배포본을 브랜치로 나누고, 공통 수정은 cherry-pick 으로만 옮기는 규칙을 문서로 남겼습니다.
- **결과:** 브랜치별 배포 설정이 서로 덮어쓰이는 사고 없이, 세 배포본을 함께 운영했습니다.

### 3. 로그를 보는 행위가 로그를 늘린다

- **문제:** 서버 로그를 브라우저에서 볼 수 있는 관리 화면이 필요했습니다. 그런데 조회 요청 자체가 로그에 쌓여 정작 보려는 내용을 덮었습니다.
- **해결:** 파일 mtime 이 같으면 내용도 같다는 점을 이용해, (파일 · 줄 수 · 레벨) 단위로 결과를 캐시했습니다. 화면 자신이 만든 호출은 기본으로 숨겼습니다.
- **결과:** 요청 단위 목록과 엔드포인트 집계(2xx/4xx/5xx · 평균 · 최대 응답시간)를 가볍게 볼 수 있게 됐습니다.

## 주요 기능

- **학습자:**
  - 사전역량진단 설문과 레이더 결과
  - 추천 목록과 추천 이유, 추천 지식맵(force 그래프)
  - 학습 이력에 따른 분기, 즐겨찾기, 만족도 피드백(비속어 필터 포함)
  - 기관 사이트용 iframe 임베드 모드
- **백오피스:**
  - 대시보드: KPI · 도넛 · 시간대 히트맵 · 인기 키워드
  - 학습자 「성장 분석 (AI)」 탭과 AI 추천 학습 로드맵
  - 콘텐츠 AI 메타데이터 편집, 엑셀 일괄 등록, 이벤트 응모 관리

## 배운 점

운영 환경을 내가 통제할 수 없을 때는 **실수가 들어올 틈 자체를 줄이는 것**이 가장 확실한 대응이라는 것을
배웠습니다. 모듈 경계, 배포 브랜치 규칙, 설치 가이드는 모두 그 틈을 막기 위한 장치였습니다.
