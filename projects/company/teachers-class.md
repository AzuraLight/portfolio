# 티처스 클래스

> 교재를 만드는 에디터부터 수업을 여는 플레이어까지 — 교육 서비스 프론트엔드 전체를 혼자 설계하고 만든 모노레포.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.09 – 2026.10 |
| 역할 | 프론트엔드 단독 개발 — 설계 · 구현 · 테스트 · 배포 |
| 기여도 | 프론트엔드 100% (커밋 520여 건) |
| 기술 | Vue 3.5, TypeScript, pnpm + Turborepo, Pinia, TanStack Query, vue-i18n, Tailwind v4, CodeMirror 6, Vitest, Playwright, Storybook, Docker, Kubernetes |

## 배경

교사가 KIT(교구 + 차시 교재)를 골라 수업을 진행하는 서비스입니다. 관리자는 교재를 만들고 운영을 관리하며, 교사는
교재로 반을 대상으로 수업합니다. 이전에는 관리자와 서비스가 별도 저장소로 나뉘어 있었고, 이를 하나의 모노레포로 합치며
전체 구조를 새로 설계했습니다.

## 담당 업무

- 관리자 앱 · 교재 에디터 · 강사용 앱 · 수업 Player 를 하나의 모노레포로 재구성
- 교재 에디터 전체 설계와 구현
- 수업 Player 와 도구(애드온) 구현
- API 계약 패키지, 테스트, CI/CD 와 Kubernetes 배포 구성

## 문제와 해결

### 1. 에디터에서 만든 교재를 수업에서 그대로 재생해야 한다

- **문제:** 초기 수업 Player 는 표본 교재만 재생했습니다. 관리자가 에디터에서 만든 교재를, 미리보기에서 본 모습 그대로 수업에서 보여 줘야 했습니다.
- **해결:** 에디터 안에 있던 교재 렌더러를 독립 패키지로 분리하고, 에디터 미리보기와 Player 가 같은 렌더러를 쓰게 했습니다(ADR 0015).
- **결과:** 미리보기와 실제 수업 화면이 같은 코드로 그려져, 두 화면이 어긋날 여지가 구조적으로 없어졌습니다.

### 2. 레이아웃이 늘 때마다 여러 곳을 고쳐야 한다

- **문제:** 레이아웃마다 폼, 글자 수 한도, 도움말, 가이드 문서를 따로 관리하고 있었습니다.
- **해결:** 레이아웃 13개 묶음을 선언(데이터)으로 정의하고, 폼 · 한도 · 도움말 · 가이드 페이지가 모두 선언에서 만들어지게 했습니다. 선언에는 글 대신 메시지 키만 두어 다국어에도 대응했습니다.
- **결과:** 레이아웃 추가가 선언 하나를 쓰는 작업으로 줄었습니다.

### 3. 여러 명이 동시에 고치면 내용을 잃는다

- **문제:** 관리자 여러 명이 같은 차시를 편집할 수 있었고, 2초마다 자동 저장되는 구조였습니다.
- **해결:** 차시 편집 잠금, 저장 충돌 창(내 수정과 서버 판 비교), 이 탭의 판 기록과 되돌리기, 새로고침 복원을 넣었습니다.
- **결과:** 동시 편집이나 새로고침 상황에서도 편집 내용이 사라지지 않게 됐습니다.

### 4. 서버 명세가 바뀌면 화면이 조용히 깨진다

- **문제:** 관리자 · 서비스 API 가 자주 바뀌는 단계였습니다.
- **해결:** 명세 원본 · 생성 타입 · 클라이언트를 `packages/api` 하나에 모으고, `api:check` 로 명세와 타입의 어긋남을 검사했습니다(ADR 0017).
- **결과:** 명세가 바뀌면 배포 전에 타입 검사에서 먼저 드러납니다.

## 주요 기능

- **교재 에디터:** 폼 · 문서 · JSON 세 가지 편집 방식을 제공합니다.
  - JSON 편집은 CodeMirror 6 기반이고, 스키마 자동완성 · 인라인 오류 · 빠른 고침이 들어 있습니다.
  - 교안 JSONL · 마크다운 가져오기, 교재 JSONL 내려받기를 지원합니다.
  - 미리보기 새 탭은 BroadcastChannel 로 실시간 반영됩니다.
  - 명령 찾기 ⌘K, 교재 전체 찾아 바꾸기 같은 단축키가 있습니다.
- **수업 Player:** Active Player 엔진 위에 도구를 애드온으로 꽂습니다.
  - 도구: 필기 · 타이머 · 퀴즈 · 참고자료 · 스티커 메모장
  - 발표자 화면과 학생 창이 연동됩니다.
- **강사용 앱:** 랜딩 → KIT 둘러보기 → 수업 준비 → 수업 진행 → 마무리 → 리포트 흐름과 My Teachers 를 만들었습니다.
- **관리자 앱:** 도메인 · 클래스 · KIT · 차시 · 진열대 · 자산 라이브러리 · 수업 이력 · 회원 관리 화면을 만들었습니다.

## 아키텍처

```text
apps/admin               관리자 앱 + 교재 에디터
apps/service             강사용 앱 + 수업 Player
packages/shared          공통 UI · 레이아웃 선언 · 테마 (단일 원본)
packages/lesson-renderer 교재 렌더러 — 에디터와 Player 가 함께 사용
packages/api             OpenAPI 명세 · 생성 타입 · 클라이언트
```

- 두 앱 모두 Feature-Sliced Design 구조이고, 설계 결정 17건을 ADR 로 기록했습니다.
- 배포는 Dockerfile 하나로 앱별 이미지를 만들어 Kubernetes 에 올립니다. 런타임은 의존성 없는 Node 서버(정적 서빙 · SPA 폴백 · API 프록시)입니다.

## 배운 점

문제를 하나씩 고치는 것보다 **그 문제가 다시 생길 수 없는 구조**를 먼저 찾는 편이 결국 빠르다는 것을 배웠습니다.
렌더러 분리, 선언형 레이아웃, API 계약 패키지는 모두 "같은 실수를 두 번 하지 않는 장치"였습니다.
