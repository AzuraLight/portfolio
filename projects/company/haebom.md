# 해봄 AI 플랫폼 — 공개 화면 · 관리자 화면

> 광명 지역에서 시민이 올린 문제(시민문제 카드)와 그 문제를 풀 수 있는 기업(해결 카드)을 AI 로
> 매칭하는 플랫폼입니다(발주: 이티랩). API 서버는 다른 개발자가 맡았고, 저는 **프론트엔드
> 저장소**를 분리해서 개발했습니다.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.08 – 2026.09 |
| 역할 | 프론트엔드 저장소 개발 (커밋 230여 건) |
| 스택 | React 19 · TypeScript · Vite · TanStack Query · react-router 7 · Tailwind v4 · oxlint · stylelint |
| 배포 | Docker(nginx-unprivileged) → Kubernetes. 파이프라인으로 자동 배포 |

## 주요 구현

- **저장소 분리.** 모노레포의 사용자 화면을 독립 저장소로 분리했습니다. 공유 모듈 없이 REST 계약만 공유합니다. 화면은 상대 경로 `/api` 만 호출하고 절대 URL 을 쓰지 않습니다. 최종 도메인이 발주기관 명의라 배포 시점에 정해지기 때문입니다.
- **공개 화면**
  - 홈과 시민문제 · 기업 해결카드 목록·상세: 무한 스크롤, 스티키 필터
  - 해봄지도: 행정동 폴리곤, 지역 선택
  - 기업 등록 · 해결카드 등록(PC 판), 시민문제 수정 흐름(PUT)
  - 주소 검색 연동
- **관리자 화면**
  - 로그인과 관리자 셸, 검수(시민문제 · 해결카드 상세)
  - 기업 관리(페이지네이션), 매칭 목록·결과, 데이터 관리, 설정(운영 토글)
  - 화면별 필요 권한을 라우트와 메뉴에 연결했고, 세션 만료는 한곳에서 처리합니다
- **구조:** `src` 를 `public / admin / shared` 로 나누고 import 차단 린터로 경계를 지켰습니다. 원시 토큰을 shared 스타일로 올렸고, 주요 메뉴는 정본 하나로 모았습니다.
- **API 타입 생성:** 공개 API 스키마에서 타입을 자동 생성합니다(swagger-typescript-api).
- **소식 게시판 연결:** 헤드리스 CMS(Ghost)의 소식·이야기 콘텐츠를 읽어 메뉴에 붙였습니다.

## 지킨 원칙

- 위치는 동 단위로만 표시하고, 원래 좌표는 노출하지 않습니다.
- 담당자 연락처와 시민문제 원문은 공개하지 않습니다.
- 확률로 읽히는 표현(「해결 가능성 82%」)을 쓰지 않습니다. 「적합도」로 표기합니다.
