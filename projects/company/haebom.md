# 해봄 AI 플랫폼

> 지역 문제와 해결 기업을 잇는 매칭 플랫폼의 프론트엔드 — 모노레포에서 독립 저장소로 분리하고 공개 · 관리자 화면을 구현.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.08 – 2026.09 |
| 고객사 | 이티랩 |
| 역할 | 프론트엔드 저장소 개발 (API 서버는 다른 개발자 담당) |
| 기여도 | 프론트엔드 저장소 커밋 230여 건 |
| 기술 | React 19, TypeScript, Vite, TanStack Query, react-router 7, Tailwind v4, oxlint, stylelint |

## 배경

광명 지역 시민이 올린 문제(시민문제 카드)와, 그 문제를 풀 수 있는 기업(해결 카드)을 AI 로 매칭하는 플랫폼입니다.
처음에는 API 와 화면이 한 모노레포에 있었습니다. 프론트엔드와 백엔드가 각자의 속도로 배포할 수 있도록 화면을 분리했습니다.

## 담당 업무

- 사용자 화면을 독립 저장소로 분리하고 빌드 · 배포 구성
- 공개 화면: 홈, 시민문제 · 해결카드 목록과 상세, 해봄지도, 기업 · 해결카드 등록, 시민문제 수정
- 관리자 화면: 로그인 · 검수 · 기업 관리 · 매칭 목록과 결과 · 데이터 관리 · 설정
- 소식 게시판(헤드리스 CMS) 연동

## 문제와 해결

### 1. 프론트엔드와 백엔드가 서로를 기다린다

- **문제:** 한 저장소에서 화면과 API 가 함께 배포되어, 한쪽 변경이 다른 쪽 배포를 붙잡았습니다.
- **해결:** 사용자 화면을 독립 저장소로 분리하고, 공유 모듈 없이 REST 계약만 공유했습니다. 공개 API 스키마에서 타입을 자동 생성해 서버 변경이 화면에 바로 드러나게 했습니다.
- **결과:** 두 저장소가 독립적으로 개발 · 배포됩니다.

### 2. 최종 도메인이 아직 정해지지 않았다

- **문제:** 최종 도메인이 발주기관 명의라 배포 시점에야 정해졌습니다.
- **해결:** 화면은 상대 경로 `/api` 만 부르고, 개발은 Vite 프록시가, 운영은 앞단 서버가 API 로 넘기게 했습니다. 소스에는 절대 URL 을 쓰지 않았습니다.
- **결과:** 도메인이 바뀌어도 코드를 고칠 필요가 없습니다.

### 3. 공개 화면의 개인정보

- **문제:** 시민이 올린 문제에는 위치와 원문이 들어 있습니다.
- **해결:** 좌표는 동 단위로만 표시하고, 시민문제 원문과 담당자 연락처는 공개하지 않았습니다. 「해결 가능성 82%」처럼 확률로 읽히는 표현 대신 「적합도」를 썼습니다.

## 주요 기능

- **목록:** 무한 스크롤, 스티키 필터, 맨 위로 버튼
- **해봄지도:** 행정동 폴리곤과 지역 선택
- **등록:** PC 판 기업 · 해결카드 등록 흐름(모달), 주소 검색, 서버 코드표 기반 선택지
- **관리자:** 화면별 필요 권한을 라우트와 메뉴에 연결, 세션 만료 일괄 처리
- **구조:** `src` 를 `public / admin / shared` 로 나누고 import 차단 린터로 경계 유지

## 배운 점

경계를 먼저 정하면 협업이 쉬워진다는 것을 배웠습니다. "무엇을 공유하지 않을지"를 정하는 것이, 무엇을 공유할지 정하는 것만큼 중요했습니다.
