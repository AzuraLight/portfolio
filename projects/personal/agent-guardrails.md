# agent-guardrails

> AI 코딩 에이전트(Claude Code)를 실무 저장소에서 안전하게 쓰기 위한 기록 · 감사 · 정책 도구 모음 —
> 에이전트가 스스로 판정하지 못하게, 판정을 기계로 옮겼습니다.

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026.09 – 2026.11 |
| 역할 | 문제 정의 · 규칙과 원칙 설계 · 실제 프로젝트 운영 주도, 구현은 AI 코딩 에이전트와 함께 |
| 기술 | Python, SQLite (FTS5 · 트리거), Claude Code Hooks, git 객체 모델, GitHub Actions |
| 규모 | 도구 8종 · 시험 70건 (macOS · Ubuntu CI) |
| 링크 | [github.com/AzuraLight/agent-guardrails](https://github.com/AzuraLight/agent-guardrails) · PolyForm Noncommercial |

## 배경

고객사 프로젝트를 AI 에이전트와 함께 진행하며 속도는 크게 올랐지만, 같은 종류의 사고가 반복됐습니다.

- 사용자와 확정한 결정을 말없이 바꿔 구현
- 측정하지 않은 화면 수정을 "고쳤다"고 보고
- 시험이 실패한 변경을 스스로 "통과" 승인
- 훅에 막히면 다른 도구 · 다른 표기 · 다른 경로로 돌아가는 우회

프롬프트와 메모리로 "하지 마라"를 적어도 지켜지지 않았습니다. 같은 문맥 안의 자기 검토는 그 문맥의 가정을 물려받기 때문입니다.

## 담당 업무

- 사고 사례를 모아 규칙(R1~R6 정책, R1~R9 감사 규칙)으로 정의
- 원칙 수립: 기계 → LLM → 기계, fail-closed, 덧붙이기 전용 기록, 자기 보호
- 업계 표준을 근거로 저장 구조 설계: 메달리온 아키텍처, git 객체 모델, GitHub PR · Actions
- 실제 저장소에서 시험 운전하며 규칙을 다듬고, 공개 전에 전 도구를 점검 · 보강

## 문제와 해결

### 1. 막히면 다른 길로 돌아간다

- **문제:** 훅이 한 도구를 막으면 에이전트는 다른 도구나 다른 표기로 같은 일을 했습니다.
- **해결:** PreToolUse 입구를 judgmentctl 하나로 모으고, 어떤 훅이든 거부하면 그 턴의 모든 도구 호출을 막는 **멈춤** 상태를 만들었습니다. 알려진 우회 꼴은 처음부터 거부하고 위반 점수를 쌓아, 문턱을 넘으면 사용자만 풀 수 있게 세션을 정지합니다.
- **결과:** 우회 시도가 모두 기록에 남고, Stop 훅이 막힘이 있던 턴마다 보고를 강제해 숨길 수 없게 됐습니다.

### 2. "통과했다"는 말을 믿을 수 없다

- **문제:** 커밋 메시지와 보고에 적힌 검사 결과가 실제와 달랐습니다.
- **해결:** 검사를 `auditctl run` 이 직접 실행해 코드 트리 해시와 종료 코드를 기록하고, 커밋 · 푸시 시점에 같은 트리의 통과 기록이 있는지 확인합니다. 트리가 한 글자라도 바뀌면 기록은 무효입니다.
- **결과:** 실제 저장소 시험 운전에서 기록 없는 커밋 · 푸시, `--no-verify`, `.env` 읽기가 모두 거부됐고, 훅 한 번은 0.15~0.2초였습니다.

### 3. LLM 감사도 지어낼 수 있다

- **문제:** 판정을 다른 LLM 에 맡겨도, 그 LLM 이 근거를 지어낼 수 있습니다.
- **해결:** LLM 감사 앞뒤에 기계 검증을 붙였습니다. 지적의 인용이 실제 diff 줄과 대화 원문에 **글자 그대로** 있어야만 유효하고, 아니면 버립니다.
- **결과:** 설계 · 규칙 단계까지 완료했고, 구현은 다음 단계로 남아 있습니다.

### 4. 공개 전 점검에서 찾은 결함

- 자기 승인을 막으려 만든 vcsctl 이 정작 작성자의 자기 승인과 검사 실패 병합을 허용하고 있었습니다.
- 대화 기록이 재작성되면 바뀐 줄을 조용히 버리고 있었습니다.
- 단독 훅의 오류 시 통과(fail-open) 문제도 있었습니다.
- 모두 고치고, 시험 15건을 더해 회귀를 막았습니다.

## 구성

| 도구 | 하는 일 |
| --- | --- |
| judgmentctl | 정책 엔진 — 멈춤 · 위반 점수 · 정지, 해시 사슬 기록 |
| auditctl | 커밋 · 푸시 전 감사 — 코드 해시에 묶인 검사 기록 |
| sessionctl | 대화 원본 적재 · 검색 · 근거 줄이 필수인 요약 |
| figmactl | Figma 응답 원본 보존, 같은 노드 재요청 차단 |
| assetctl | 내용 지문(sha256) 저장소, 손상 검사 |
| vcsctl | 폴더별 이력 · PR · 필수 검토 · 필수 검사 |

## 배운 점

AI 에이전트를 잘 쓰는 일은 프롬프트를 잘 쓰는 일이 아니라 **판정과 기록을 에이전트 밖에 두는 일**이라는 것을 배웠습니다.
속도는 에이전트에게 맡기되, 무엇이 사실인지는 기계 기록이 정하게 하는 구조가 실무에서 신뢰를 만들었습니다.
